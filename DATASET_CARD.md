# Dataset Card: LLM Research Bench Procedural Task Corpus

## Краткое описание

Корпус содержит 100 коротких процедурных задач из 50 семейств. Для каждой задачи
даны одна постановка, три reference solutions на естественном языке и три
reference solutions на Python. Корпус создан специально для исследования влияния
формы представления на предсказательную неопределённость авторегрессионных
языковых моделей и заморожен перед confirmatory Experiment 6.

Корпус не является внешним стандартизованным benchmark и не предназначен для
оценки общей способности модели программировать или решать алгоритмические
задачи.

## Структура записи

Корневой JSON-объект — массив задач. Каждая запись содержит:

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | уникальный идентификатор задачи |
| `family` | string | идентификатор семейства; каждое семейство содержит две задачи |
| `task` | string | краткая постановка процедурной задачи |
| `nl` | array[string] | три естественно-языковых reference solutions |
| `python` | array[string] | три Python reference solutions |

Корпус не содержит train/validation/test split: единицей confirmatory-анализа
является задача, а семейства используются для проверки устойчивости.

## Создание корпуса

Корпус был синтетически создан специально для проекта ориентировочно 15–16
сентября 2026 года, непосредственно перед confirmatory Experiment 6. Автор проекта
задал исследовательский дизайн:

- 100 процедурных задач;
- 50 различных семейств;
- не более двух задач одного семейства;
- три NL- и три Python reference solutions для каждой задачи;
- заморозка корпуса и повторное использование без изменения.

ChatGPT существенно участвовал в создании задач, их формулировок и всех reference
solutions. Автор проекта определил требования, экспериментальный дизайн, критерии
валидации и решение о замораживании корпуса. Готовый корпус впервые появился в
истории Git 18 сентября 2026 года в коммите
`4cfeee1e3d3954c211cee68589d90a926e9ad24a`.

Подробная авторская декларация находится в
[`publication/representation_predictive_uncertainty/CORPUS_AUTHOR_DECLARATION_RU.md`](publication/representation_predictive_uncertainty/CORPUS_AUTHOR_DECLARATION_RU.md),
а технический аудит — в
[`publication/representation_predictive_uncertainty/TASK_CORPUS_PROVENANCE_AUDIT_RU.md`](publication/representation_predictive_uncertainty/TASK_CORPUS_PROVENANCE_AUDIT_RU.md).

## Внешние источники и provenance

LeetCode, HackerRank, HumanEval, MBPP, учебники и другие опубликованные коллекции
намеренно не использовались и не адаптировались при создании корпуса. Задачи
генерировались для данного исследования.

Алгоритмические сюжеты — поиск, сортировка, подсчёт, обработка строк, списков,
словарей и матриц — общеупотребительны. Поэтому данная декларация не доказывает
уникальность алгоритмических идей и не исключает случайные текстовые или
содержательные совпадения с публичными учебными материалами. Технический аудит и
выборочный поиск точных фраз не обнаружили источник корпуса, но не являются
исчерпывающим provenance-аудитом всего публичного пространства.

## Валидация

После генерации выполнялись структурная проверка и автоматическая проверка
синтаксической корректности Python solutions. Проверить frozen-корпус можно так:

```powershell
Push-Location .\experiment6_confirmatory
python .\validate_tasks.py
Pop-Location
```

Ожидаемый результат: 100 задач, 50 семейств, 300 NL solutions, 300 Python
solutions и 600 траекторий. Синтаксическая проверка не равна доказательству
семантической корректности каждого решения для всех возможных входов.

В Experiment 8 новые представления исходных задач создавались
детерминированными преобразованиями из общего intermediate representation. LLM и
внешние API для генерации этих экспериментальных стимулов не использовались.

## Предназначенное использование

Корпус предназначен для:

- контролируемого сравнения предсказательной неопределённости при разных формах
  представления одного процедурного содержания;
- воспроизведения Experiments 6–8 этого репозитория;
- методических исследований, сохраняющих парность задач и reference solutions;
- проверки новых метрик при явном раскрытии любых изменений корпуса.

## Использование вне назначения

Корпус не следует интерпретировать как:

- репрезентативную выборку реальных программных задач;
- benchmark общей корректности, понимания или качества программирования;
- доказательство отсутствия memorization или training-data contamination;
- источник персональных, социальных или демографических выводов;
- основание приравнивать token entropy к correctness, knowledge, understanding
  или calibrated confidence.

## Ограничения и риски

- Задачи и reference solutions созданы с существенным участием одной LLM.
- Независимая ручная проверка всех 600 reference solutions ещё не выполнена.
- Отдельные формулировки могут быть шаблонными и лексически близкими.
- Общеупотребительные алгоритмические задачи могут иметь аналоги в открытых
  источниках даже при отсутствии намеренного заимствования.
- Корпус мал, искусственно сбалансирован и охватывает только короткие процедурные
  задачи.
- Экспериментальные результаты относятся к зафиксированным моделям, revisions и
  способу teacher forcing, а не ко всем языковым моделям.
